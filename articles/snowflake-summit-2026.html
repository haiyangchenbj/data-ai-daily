SnowConvert AI + Standard Warehouse Gen 2

Horizon Context — 语义上下文层

三步能力：Collect（5 个外部元数据连接器：PostgreSQL、SQL Server、Tableau、Power BI、dbt）→ Enrich（列级血缘、AI 生成文档）→ Activate（混合语义+关键词搜索）。配合 Semantic Studio（无需 SQL 定义业务逻辑）和 Semantic View Autopilot（自动维护语义视图）。54 家厂商参与的 Open Semantic Interchange (OSI) 规范已定稿——这可能是最有长期影响力的生态举措。

AI Agent Identity — 加密可验证的 Agent 身份

关键架构决策：Agent 不继承用户凭证，而是拥有独立加密身份。基于 Agent 类型的 RBAC、完整审计追踪、Agent 间权限隔离。Kleinerman 原话："传统安全模型是为人类用户设计的，而非自主软件代理。"配合 Natoma 收购（企业 MCP 平台），Snowflake 正在将治理从"数据访问"延伸到"AI 行为"。

八、Data Gravity 论：结构性判断

前沿模型已经成为托管商品。数据不是。数据有重力——它在物理上、法律上、操作上都很昂贵，不能随便搬动。因此，数据所在的平台将成为 AI 工作负载运行的平台。

对 CTO 的实际含义：不要从"谁家模型更好"出发做架构决策。从这三个问题出发：(1) 你的运营数据实际在哪里？(2) 你未来 18 个月的 AI 工作负载需要什么模型？(3) 你的一年治理承诺是什么？同样的逻辑适用于 Databricks 和微软 Fabric——数据在哪里，Agent 运行时就在哪里。

十、底线：三层判断

短期（6–12 个月）
  • Summit 叙事 + Q1 财务构成正向催化剂
  • 产品从功能列表走向"两个清晰的 Agent 产品线"
  • 治理叙事从"我们也有"升级为架构让 Agent 治理成为可能
  • ⚠ 产品大多处于 Preview/早期 GA
  • 2026 H2 的实际企业采用率是真正的验证
中期（12–24 个月）
  • 竞争格局将决定性收窄——三家不可能平分市场
  • 数据的重力决定 Agent 的运行位置
  • Snowflake 在治理和结构化数据场景有结构性优势
  • Databricks 在 ML 原生和开源生态上更强
  • 会有一个赢家吃掉大部分"用数据做 AI"的工作负载
长期（24 个月+）

Snowflake 的目标不是成为"更好的数据仓库"，而是成为"企业 Agent 的控制平面"。如果"模型商品化"的前提成立、如果"治理=壁垒"的假设成立、如果"数据重力 > 模型重力"的判断成立——那么 Snowflake 在 Agent 时代的卡位是逻辑自洽的。但这一切的前提是：Agent 确实成为企业运营的主流方式，而不仅仅是下一个被过度炒作的 AI 功能。
