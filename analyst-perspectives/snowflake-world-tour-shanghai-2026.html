01

核心判断

Snowflake World Tour 上海站不是在发布面向中国市场的产品，而是在向一个特定客群投放一套已在全球验证过的叙事。这套叙事的核心是：企业 AI 的瓶颈不在模型，而在上下文；数据平台要从存储与查询层升级为智能体控制平面（Agentic Control Plane），把模型选择、身份、策略、成本收拢到同一层。

这个战略的前提是：模型是租来的，意义是自己的。前提在全球范围内成立，在中国市场同样成立，只是 Snowflake 在中国区只搬来了能力的载体，没有搬来让它最强的那个部分。

02

具体观察

从这场大会的呈现方式中提炼的五个判断
观察 01

被本地化的只有讲故事的人，不是数据的地基

上海站的架构、术语、演示路径乃至准确性阶梯，与三个月前的全球大会高度一致；变化的是台上的面孔换成了中国区团队，案例换成了本地场景与国产模型。

  • 这种平移本身就是一个判断：Snowflake 在中国不打算为本地需求重新设计产品，而是把已经跑通的全球叙事，投给一群特定的人。
  • 这决定了它在这里的竞争面貌：它服务的客群是那些本来就在用、或者打算用全球产品的企业，与本地厂商的客群不重叠。
  • 反过来看，这也意味着中国区的产品演进节奏跟随全球，不由本地需求独立驱动。
观察 02

“数据云”这个品牌承诺在中国是打折兑现的

全球范围内，Snowflake 最不容易被复制的能力不是存算分离，也不是 SQL 引擎的性能，而是跨组织的数据共享网络，一个组织把数据发布出去，另一个组织直接消费而不必复制一份。这套网络效应需要账户之间彼此可达。

  • 中国区是独立实例、独立域名、独立签约主体；全球账户与中国账户互不访问，数据市场在境内不开放。
  • Snowflake 全球业务中最能说明其网络效应的那个指标，在中国区没有对应形态。
进入中国拿到的是一套强大的单点平台，付出的是网络效应缺失。这是一次能力与网络的置换，而不是一次区域扩张。
观察 03

上下文之争的本质是“谁来定义企业的语言”，而定义权天然带着属地属性

业务本体、语义视图这类东西的定义对象，是客户自己的业务规则：财年怎么切、快照表怎么读、哪些机会要从统计里剔除。这与平台注册在哪个区域无关，却与谁来做定义这件事高度相关。

  • 一家企业要在境内把这套东西建起来，干活的人得熟悉它所在行业的合规约束、报表习惯和系统格局。
  • Snowflake 把这一环交给了咨询与实施伙伴，这是务实的选择，也意味着产品价值的最后一公里由第三方兑现，平台自身对交付质量的控制力相应减弱。
观察 04

它在中国要面对的对手，不是它在全球的对手

Snowflake 的全球竞争叙事建立在与 Databricks 的镜像对抗上，仓库对湖仓、治理对工程。这套对抗在中国基本不成立：Databricks 没有同等量级的本地落地。

  • 真正在承接“数据平台 + AI 智能体”这个需求的是本地云厂商，而且恰好在本届大会前一周，权威机构把这一品类的本土领导者排名给到了它们。
  • Snowflake 中国区不打这场仗，客群、交付形态与定价逻辑都不同。
  • 两条平行市场，短期不交汇，长期是否交汇取决于跨国企业的境内数据政策要不要收紧。
观察 05

“开放”在中国区多了一层含义

全球语境下，Snowflake 讲开放是为了消除“被一家厂商锁定”的顾虑：支持开放表格式、兼容外部计算引擎、承诺模型可替换；会上那句“没有人希望你因为技术原因被锁定”讲的就是这件事。

  • 在中国区，开放还承担了第二个功能：它是绕开单一云区域限制的手段。
  • 通过对象存储的兼容协议，中国区客户的数据资产可以落在非 AWS 的国产云存储上，AWS 从“唯一地基”降为“其中一个入口”。
  • 这让 Snowflake 中国区不被单一云商绑定，也让它与本地云厂商的关系从纯竞争变为既竞争又合作，对方既是可能的存储底座，又是正面战场的对手。
03

产品全景

前述观察的事实支撑。上海站没有中国区专属的产品发布，展示的是一套全球架构的完整拼图。
架构层智能体控制平面

Agentic Control Plane

本届大会的核心概念。Christian Kleinerman（全球产品总裁）把企业级智能体拆成四个必须同时成立的要素：AI 模型、企业数据与上下文、连接企业系统的软件与应用，以及统一管理前三者的控制平面。

  • 他强调这不是面向未来数年的路线图，而是已经可以进入实际部署的架构。
  • 控制平面要回答的问题，从过去的“谁能看哪些数据”扩展为：智能体可以调用什么模型、访问哪些数据、连接哪些系统、执行哪些动作、出了问题能否追溯、成本如何控制。
公开预览可用区域未公布

Cortex AI Gateway

上海站宣布其进入公开预览，同期英文报道的措辞为“计划开放”，可用范围与区域未公布。企业级 MCP 网关，能力来自 2026 年 5 月完成收购的 Natoma。

  • 它把智能体对外部的调用收拢到一处：模型路由（按成本、延迟、能力、数据驻留地分发请求）、身份验证、策略执行、审计记录、预算上限。
  • 官方称支持 100 个以上 MCP 服务器。
  • 治理策略继承自 Horizon Catalog，AI 的权限体系复用数据已有的权限体系，不另建一套。
并入 Horizon Context

业务本体 Business Ontology

由 AI 技术战略首席架构师贾天下主讲。核心主张是一句话：事实只存一份，业务含义单独管理，剩下的让系统自动生成。

  • 他用“图纸与楼”区分本体与知识图谱：本体定义抽象规则（球员是一种人，可以任职于俱乐部），知识图谱记录具体事实（某球员效力于某俱乐部，会随时间变化）。
  • 价值出现在业务变化时：新增一种实体、调整一组关系，改的是业务定义，不必重新建表或重写下游查询。
  • 查询语句没写错，缺的是业务规则：快照表如何读取、财年如何定义、哪些机会要剔除。
  • 落地方向包括亚太一家银行的反洗钱（通过交易方、账户、交易之间的关系识别单表看不到的关联）、中东一家主权财富基金建模私募市场、电通旗下 Merkle 采用同类架构。
现场给出的反例比正例更有说服力 AI 回答“本季度合同总额”时给出 42 亿美元，正确答案是 8,400 万美元。
GA

Horizon Context 与 Semantic View

上下文层的两个组件。Semantic View 是 Snowflake 内的原生数据库对象，把经过治理的指标、维度、关系、同义词和已验证示例存在仓库里，向 Cortex Analyst、CoCo、CoWork、Cortex Sense 供给统一定义。Horizon Context 在其上做治理化的收集、充实、激活管线，向智能体提供企业语义。

边界值得标注 Semantic View 只在 Snowflake 内可见，不触及仓库之外的数据；不原生呈现于 Power BI、Excel、Tableau 等业务侧工具；截至 2026 年中无跨账户复制能力。
GA

CoCo 与 CoWork

智能体控制平面的两个入口。CoCo 面向技术用户（原 Cortex Code），CoWork 面向业务用户（原 Snowflake Intelligence），共享技能、深度研究、MCP 连接等能力。

上海站演示的职业体育联赛场景把它们串成一条链：

五类业务系统数据进入统一目录→ 敏感数据识别打标与权限治理→ Semantic View 统一定义核心指标→ CoWork 生成经营简报、Deep Research 交叉分析、MCP 连接协作系统执行动作
  • 中国区演示中的协作出口是钉钉。

上下文栈的分层

Snowflake 把企业上下文拆成由下至上的四层，逐层补齐从“数据可用”到“智能体可控”的距离。

数据与目录层
Horizon Catalog · Iceberg REST Catalog API · 开放表格式
解决“数据在哪里、能不能被外部引擎读到”。
语义层
Semantic View · Semantic Studio · Semantic View Autopilot
解决“指标怎么定义、由谁定义”，把治理后的定义存入仓库。
本体层
Business Ontology（并入 Horizon Context）
解决“业务对象之间是什么关系”。本届大会的加码重点，事实与含义分离管理。
控制平面
Cortex AI Gateway · Agent Identity · Agent Policy · 预算控制
解决“智能体能做什么、花了多少、有据可查吗”，治理对象从数据访问转向智能体行为。

两家在同一周被同一家机构定了位

9 月 1 日，IDC 发布《中国 Data Agent 2026 厂商评估》：18 家入选，仅 4 家进入领导者象限，阿里云居最领先位置；IDC 同时预测到 2028 年 60% 的中国 500 强企业将部署企业级 Data Agent。

这个结论与一周后 Snowflake 在上海的主命题指向同一件事：数据平台与智能体的结合点，已成为行业共识，不再属于某一家厂商的路线选择。

差别在于，本土厂商在该品类上拿到的评价、交付形态与合规路径，都是为境内市场定制的。

上述准确率均为各厂商自披露口径，题集与测试条件不同，相互之间不具备可比性。

Snowflake 在中国区的优势与风险
优势
  • 全球产品的完整能力与迭代速度
  • 跨国企业总部既有的合作关系
  • 治理能力的长年积累
  • 通过对象存储兼容协议实现的国产云存储接入
风险
  • 跨组织数据共享网络在中国区缺位
  • 无自助开通拉长了获客链路
  • 数据市场不开放削弱了平台对数据提供方的吸引力
  • 客群集中在跨国企业与出海团队因而市场天花板受限
  • 本地厂商在私有化部署与信创适配上的结构性优势

对买方的建议

按角色给可执行判断
数据平台负责人
境内落地前先要一份中国区与全球区的功能差异清单。官方文档已声明“某些功能可能无法在中国区域使用”，但未逐项公开，按全球版能力表做境内规划会踩空。
  • 语义层与本体层的投入值得提前启动：定义对象是客户自己的业务规则，这部分资产与平台选型解耦，即便未来更换平台也有残值。
  • 同时留意 Semantic View 的既有边界，即只在 Snowflake 内可见、不原生供给业务侧 BI 工具、截至 2026 年中不支持跨账户复制，本体资产目前的形态是平台内对象，尚未成为可携带的行业标准。
AI 平台负责人
智能体治理的评估重点在覆盖面。中心化网关只在关键智能体流量真正经过它时才产生价值，绕过控制层的调用会留下策略与审计缺口。
  • 采购前要求厂商说明第三方智能体、既有自研 Agent 的纳入方式。
  • 上下文层的收益（准确率提升、单次调用成本下降）被作为卖点呈现，但测试条件未披露，建议以自有高难度问题集复现一次，这一步的成本远低于按官方数字做架构决策的风险。
采购
合同层面确认三件事：
  • 中国区功能差异清单作为附件。
  • Keynote 披露的性能数字是否可复现（即是否接受以双方约定的基准做验收）。
  • 退出条款中的数据处理与迁移责任划分。
  • 签约主体是授权运营方，Snowflake Inc. 不是合同相对方，这会影响争议解决路径与服务水平承诺的可执行性。
  • 若是跨国企业中国分部，还需确认中国区实例与全球实例之间的数据流转机制：两者互不访问意味着跨区分析需要重建一份数据链路。
竞品厂商（含腾讯云）
Snowflake 在中国区被切掉的是它全球最强的部分：跨组织数据共享网络、数据市场、自助开通的低摩擦获客。这三项在境内都不是短期能补齐的，且与合规架构绑定。
  • 可以在两个方向上找位置：一是“数据不出境前提下的跨组织协作”，这恰好是全球方案在境内的功能空洞；二是语义与本体能力的“可迁移性”叙事。
  • 如果客户的语义资产能脱离单一平台存在，这个卖点对担心锁定的买方有分量。
  • 需要留意的是，Snowflake 开放模型选择与国产云存储接入的动作，会让“它不能接本地生态”这类简单对标失效，竞争点要落在交付形态与语义资产归属上。
07

行业延伸

竞争焦点从“数据放在哪里”转向“数据意味着什么”
本届大会提出的行业级命题，是一句放在演示页上的表述：数据平台之间的竞争，正在从“数据放在哪里”向“数据意味着什么”延伸。

这句话的落点不在 Snowflake 一家身上。

  • 过去十年，数据平台的差异化建立在物理属性上：数据能不能搬、搬得贵不贵、查询够不够快。当存储与计算分离成为标配、开放表格式成为共识，这些维度逐渐被抹平。
  • 与此同时，智能体把一个新的约束推到了台前：模型不会因为访问了数据就理解业务，它需要有人先把业务规则显性化。
  • 于是语义层与本体层从“分析项目的加分项”变成“智能体能否上生产的前置条件”。
Gartner 的判断是把通用语义层视作与数据平台、网络安全并列的关键基础设施，已超出可选分析组件的范畴。

真正的分歧不在要不要建语义层，而在语义资产归谁、能不能搬走。

路线代表语义资产的形态
平台内对象Snowflake Semantic View仓库内一等数据库对象，随权限体系治理，只能在平台内消费，无跨账户复制
开放标准Databricks Metrics（开源，基于 Open Semantic Interchange）以开放标准表达，理论上可被外部工具与引擎消费
厂商中立层独立语义层产品架设在数据平台之上，向多家 BI 与 AI 工具输出同一定义
  • 这三条路线的分野将决定一件事：企业在语义层上投入的工程与治理成本，是一项随平台绑定而贬值的沉没成本，还是一项可以跟着企业走的资产。前者的商业含义对平台厂商更有利，后者的商业含义对买方更有利。
谁定义企业的语言，谁就掌握智能体正确性的基线。

到目前为止，这个定义权的归属还没有形成标准，也没有出现被广泛接受的仲裁者。

待验证的问题

问题 1
上下文阶梯的测试条件未披露

24.1% 到 86.3% 的提升幅度很大，但厂商未说明题集难度、数据规模、语义覆盖度和人工介入比例。这类数字的行业价值取决于可复现性。缺少条件的基准，其证据效力接近演示。

问题 2
中国区功能差异清单缺位

官方仅声明“某些功能可能无法在中国区域使用”，未逐项公开。跨国企业在做境内架构规划时，实际是在信息不对称条件下决策。

问题 3
本体的维护成本与责任人未明确

业务本体的定义对象是业务规则，这决定了它天然需要业务侧参与，而不只是数据团队的工作。谁拥有本体、谁在业务规则变化时更新它、更新滞后时由谁负责。这个组织问题比技术方案更能决定本体架构的长期成败。

08

总结

Snowflake World Tour 首次落地中国，交出的是一份清晰的战略取舍：把产品能力搬进境内，把数据网络留在境外。

  • 它选择用授权运营与独立实例换取合规准入，代价是让“数据云”这个品牌名在中国区失去了最能体现其网络效应的那一层。
  • 它选择平移全球叙事，没有为本地需求重塑产品，代价是客群收窄到跨国企业在华机构与中国出海企业。
  • 这不是错误的策略。对一个受制于数据主权规则的境外平台而言，这可能是唯一可行的路径，但它划定了这家公司在中国市场的能力上限。
与此同时，本届大会提出的命题是行业级的，不因区域而打折：当模型趋同、存储与计算成为商品，决定智能体能否上生产的是企业语义的完整程度与治理水平。这条战线上，Snowflake、Databricks 与本土厂商站在同一道起跑线，且各有短板。
短期 · 6–12 个月

中国区有三个可观测的信号：

  • 通过 DCC 签约的客户数量
  • 跨国公司在华机构是否把境内数据平台从“部门级试点”提升为“区域标准件”
  • 中国区与全球区的功能差异是否开始逐项收敛

产品侧，Cortex AI Gateway 的 GA 时点是下一个可观测信号。

中期 · 12–24 个月
  • 中国市场的两条平行赛道是否交汇，取决于跨国企业的境内数据政策走向。
  • 如果境内数据驻留要求收紧、跨区流转进一步受限，Snowflake 中国区的“单点平台”定位会被强化，本地厂商在私有化与信创维度上的优势相应放大。
  • 语义层的标准之争在此期间会分出方向：开放标准路线与平台内对象路线，哪一种被更多企业接受为语义资产的存在形式。
长期 · 24 个月以上
  • 如果语义层像存储与计算分离一样成为行业标配，那么数据平台的差异化将再次转移：从“谁能建语义层”转向“谁的语义资产能被最多系统消费”。
  • 届时领先者的身份不取决于平台规模，而取决于它是否成为语义定义的事实参照系。
Strategic Planning Assumption

到 2028 年，企业级语义与本体层将从数据平台的可选能力变为标配组件，置信度中等偏高；届时差异化的来源将从“是否具备语义层”转移到“语义资产的可移植性与跨平台消费能力”，该转移对买方有利、对平台厂商不利，置信度中等。
